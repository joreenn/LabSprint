## Review policy and expansion workflow

1. Author an original item from a specific, checked reference section. Never transplant a book's question and answer choices wholesale.
2. Verify the correct answer, each distractor, units, calculations, and assumptions. Use method-specific or local reference intervals when needed.
3. Check changing information against current primary guidance. Older books can contain outdated formulas, species terminology, assay limitations, regulations, and clinical recommendations. The starter items avoid book-specific treatment recommendations and do not inherit questionable statements merely because they appear in a book.
4. Require independent MLS faculty or qualified professional review before treating an item as exam-ready. This seed has source checking by the implementation agent; it has **not** received independent expert validation.
5. Keep IDs stable; increment an item's `version` when its meaning, correct option, or rationale changes. Preserve historical attempts against the stored version so a later correction does not rewrite past results.
6. Run content validation and application tests, preview the question/rationales on a phone-sized screen, and record corrections in the project changelog.
7. Use the application's question-report workflow to capture disputed or unclear items. Investigate against the original source before changing the key.

Practice accuracy is a learning signal, not a validated probability of passing an exam. First attempts, repeat attempts, and topic coverage must remain distinguishable.
