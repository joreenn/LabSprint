## Faster study flow

The client reveals the selected answer's rationale immediately and advances to the next question locally. Saves proceed in the background. One answer POST now commits the server-scored attempt and session checkpoint atomically, replacing the older answer POST, follow-up session PUT, and next-question PUT sequence.

A durable retry queue is scoped to the signed-in user. The interface distinguishes saving and unsynced work, offers retries, and does not present an unsuccessful save as complete. Starting a new session or signing out waits for queued work to flush. Server validation, duplicate protection, and stale-device conflict handling remain essential; the immediate client result is feedback, not the authoritative database score.

This is not a complete offline mode. Loading the hosted reviewer and syncing still require a connection.

## Optional floating study timer

The floating timer is separate from answering questions. Users choose when to open or start it:

| Technique     | Behavior                                                                         |
| ------------- | -------------------------------------------------------------------------------- |
| Pomodoro      | 25-minute focus, 5-minute break, and a 15-minute break after four focus sessions |
| Deep focus    | 50-minute focus and 10-minute break                                              |
| My own rhythm | Custom focus/break lengths from 1 to 180 minutes                                 |
| Open study    | Stopwatch counting upward                                                        |

The timer supports pause/resume, reset, minimize, hide, pointer/touch dragging, and keyboard movement. It remains inside the viewport, accounts for mobile navigation space, and recalculates elapsed time from timestamps after tab/device suspension. Breaks and further focus sessions require an explicit action. Timer state and position stay on the current device and are scoped by account. No OS notification or clock permission is required.

## Password access and recovery

Password fields can show or hide their contents. The owner chose one-time recovery codes instead of configuring an email-sending domain for this release.

While signed in, users reauthenticate with their password to create a set of 10 high-entropy recovery codes. Plain codes are shown for copying or downloading; only hashes are stored in the database. A replacement set invalidates the previous set. Existing users receive a dashboard prompt to save codes while they still have access.

Forgotten-password recovery accepts the account email, an unused recovery code, and a new password. It retains the same user ID and study history, consumes the code, and revokes existing sessions. Save the codes privately: this flow cannot restore access after both the password and all codes are lost.

Migration 3 adds recovery-code storage without changing learner records. Optional email plumbing remains disabled without provider credentials and a verified sender; do not expect reset emails from the current configuration.

## Reference expansion

The bank grows from 42 to 56 original questions, adding two per subject group. The expansion uses supplied Hubbard 2nd edition, Elsevier 1st edition, Linne & Ringsrud 7th edition, and Lehman/SUCCESS! 5th edition, alongside existing Harr, Ciulla/SUCCESS!, Apollon, and Alba citations. Every added item still requires an answer rationale, distractor rationales, and a checked source reference. Existing question IDs remain intact.

Standalone Strasinger and Rodak files were suggested but have not been supplied. Their citations and coverage remain pending actual source access. Philippine Medical Technology Laws also requires current appropriate Philippine primary sources. The starter bank is neither comprehensive nor independently expert-validated. Book PDFs and extracted text are not deployed.
