# LabSprint 0.3.0 usability update

This release preserves the lavender design, navigation, question content, IDs, versions, sources, account records, scoring, option shuffling, bookmarks, database schema, and background answer queue. The owner authorized publication on 1 November 2026; see `WORK-STATE.md` for deployment and verification status.

## Inspection and changes

1. **Progress:** `src/lib/progress.ts` already preserved first attempts and used the latest answer for active missed questions. Those rules remain. Shared `progress-signals.tsx` now makes first-attempt accuracy, correct/answered denominators, unique coverage, small samples, and later corrections explicit across Overview, subject cards, topics, Progress, and Review. Unattempted accuracy is unavailable. The central small-sample threshold is five unique first attempts, a UI convention with no validated mastery implication. Repeats and corrections stay separate from baseline results. See `CONTENT-EXPANSION.md` for exact definitions.
2. **Content:** counts come from the actual bank. `npm run content:check` validates IDs, choices, answer keys, explanations, source metadata, versions, and topic mappings. The current inventory is 56 questions across seven subjects and 42 listed topics: two empty topics and 27 single-question topics. The expansion backlog identifies those gaps and an editorial workflow. No new academic material or citations were added.
3. **Practice/mobile:** `reviewer.tsx`, `views.tsx`, and `practice.tsx` retain the current session architecture. Saved sessions get a prominent Resume action; a new session gets Start practice. Phone hero copy/height is reduced and recovery guidance is collapsed, still available in Settings. Explicit single-question selection has a concise confirmation without size/style controls; replacement warnings remain. Multi-question choices follow the eligible pool and zero-match filters cannot start. Counts use singular/plural wording.
4. **Recovery:** Better Auth already supplied reset tokens, session revocation, abuse limits, and optional Resend delivery. Recovery codes and existing access remain intact. The update improves configuration availability, loading/retry/error states, field associations, expired links, and conditional/non-enumerating messages. Dispatch failures produce a fixed operational message without credentials or tokens. Email verification is assessed, not globally enabled: enabling it now could lock out existing accounts. See `ACCOUNT-RECOVERY.md` for required service configuration and a safe future rollout.
5. **Summaries:** each session now includes a compact subject/topic/result recap, first-versus-repeat labels, sync status, and expandable explanations. Expanding a recap records no answer. Saved results remain authoritative; next steps use actual misses or unattempted questions. Immediate correction is described as practice improvement, not lasting mastery. Session completion scrolls to the summary start.

## Verification

- Automated tests cover baseline preservation after retries, corrections/re-misses, unique coverage, empty/small samples, actual filters/sizes, content checks, recap history, new-question selection, account isolation, bookmarks, save/resume, retry ordering, recovery-code preservation/single use, provider token reuse/expiry, mail transport failure, and session revocation.
- Browser checks used a separate disposable local database, not existing learner data. A wrong answer followed by a correct retry kept baseline at 0/1 and coverage at one question; the missed queue cleared and the correction count became one. Bookmark preservation and session restoration after refresh passed. Inspecting recap explanations left attempts at two. The recap identified the correct retry as a repeat and offered 55 genuinely unattempted questions.
- Explicit question review showed no size/style controls. A whole subject with eight questions offered only 5 and All (8). A filter with zero eligible questions disabled Start and explained how to recover.
- Responsive checks covered 320px and 390px phone, 768px tablet, and 1366px desktop layouts. New progress/topic content had no horizontal overflow. At 320px the chart scrolls locally, and main content retains 112px bottom padding for sticky navigation. Existing safe-area navigation padding remains.
- Final results: all 32 tests passed, production build including TypeScript passed, formatting passed, and content validation passed. Browser warning/error log was empty. `WORK-STATE.md` records the completed checkpoint.
- Published on 1 November 2026. The hosted synthetic-account checks verified the same baseline/coverage/correction rules against the production database, then removed only that test account. The production deployment is READY, the browser displays version 0.3.0, and the deployment-specific request scan found no 5xx records during the checked 15-minute window. Email recovery remains unconfigured and delivery was not tested.

## Remaining work

Email reset cannot be claimed operational until a verified sender/domain, server-only mail credentials, and actual inbox/reset verification are completed. This task changes no external settings. Physical-device testing and academic/editorial review remain necessary. Structural validation does not establish medical accuracy, syllabus coverage, or readiness.

Supporting changes outside screens are pure progress/session/content helpers, focused tests, one validation command, documentation, and exposing the already-stored question version in answer responses. No dependency or database migration was added.
